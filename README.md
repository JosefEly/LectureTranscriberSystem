# What is this project?
This is a Python program that takes in a .m4a file from a program like Voice Memos (I use a Mac) and moves it, and the transcript it generates, to a matching course folder.
I'm a current student, and one of the problems I've run into studying is being able to persistently reference classes for use at a later date.
I have an unusually slow processing speed but high performance in other cognitive domains, and I often am constrained by processing material at 1x speed
in the most dense lectures. One way to solve that is by recording classes, if you have permission. But how would you access and sort through the dozens of audio files
generated by your courses? One way you can do that is by organizing them by course. But that sorting is a lot of work. What if you could automate that? And do you want to
have to thumb through an entire audio file every time you need to access one point? You could create transcripts. Hence, I had the idea to create a program that takes in audio files
of courses, transcribes them, and writes them to course-specific directories. 

# How does it work?
The program starts by transcribing, with a small local audio model, the first ten minutes of the audio file. From there, it feeds the transcript to a local LLM running in Ollama - qwen3.5:9b.
Qwen determines which course folder the audio file and transcript should go in, based on a system prompt that includes folder descriptions pulled automatically from the program's directory.
If the folder is labeled PUBLIC (public folders are ones I wouldn't mind sending to a third-party STT provider), I send the file to AssemblyAI via API, and it transcribes the audio, using a summary generated 
by Qwen for keyword biasing. For private conversations, the code uses Qwen3-ASR-1.7B-8bit instead, with the system prompt again provided by Qwen. From there, the audio file is moved
to its matching audio directory, and the transcript is written as a text file to the matching text directory (the filename is a date string based on when it was created)

# How can you set this up on your own computer?
Pull this repository and initialize the folder it's in as a virtual environment, installing the requirements with pip.
Then you need to initialize the directory structure. For the folder named, say, MICROECONOMICS, you will make a MICROECONOMICS_audio and MICROECONOMICS_transcripts.
Inside the MICROECONOMICS_transcripts folder, put in the folder description in the file called folder_description.txt. The program treats the MICROECONOMICS keyword as one root with attached audio and transcripts folders
and it looks for the description of the folder to give to Qwen inside the transcripts folder. This doesn't need to be excessively long, but it should be long enough to give the LLM an idea of what is in the folder - Qwen isn't that bright.
The repository comes with one dumping folder called Other as an example.
